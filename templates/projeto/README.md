# Templates para iniciar projetos

Escolha as seções conforme o escopo e a equipe. Remova instruções de preenchimento da versão final e use os termos do projeto.

- [README de projeto](readme-projeto.md) para objetivo, uso e navegação.
- [Especificação de projeto](especificacao.md) para requisitos derivados dos casos de uso, RAS, arquitetura, interface, planejamento, testes e operação. Cada seção pode virar um arquivo quando precisar de revisão própria.
- [ADR](adr.md) para uma decisão arquitetural com impacto.
- [Exemplo aplicado](../../exemplos/reservas-de-recursos/README.md) para ver os documentos, diagramas e issues com conteúdo fictício.
- [Ficha de diagrama](diagrama.md) para público, fronteira, fonte e revisão.
- [Plano de testes](plano-testes.md) para cenário, massa, evidência e resultados.
- [Documento de visão](visao.md) para problema, objetivos, público e fronteira do MVP.
- [Casos de uso](casos-de-uso.md) para objetivos dos atores, fluxo principal e alternativas.
- [Histórias e cenários](historias-e-cenarios.md) para fatias de valor e aceite verificável.
- [Interface e acesso](interface-e-acesso.md) para wireframes, estados e matriz de perfis.
- [Modelos nativos de issue](https://github.com/PHnsilva/base-de-projetos/issues/new/choose) para entrega, defeito e investigação.
