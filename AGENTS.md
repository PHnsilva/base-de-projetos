# Instruções para o Codex

Use esta base quando o usuário pedir para planejar, iniciar ou documentar um projeto. Trabalhe no destino identificado pelo usuário e trate a base e os projetos consultados como referências de leitura, salvo quando a tarefa for manter a própria base.

## Consulta rápida

1. Leia o escopo acordado, o `AGENTS.md` aplicável no destino e os documentos já existentes. Identifique objetivo, atores, fronteiras, restrições, versão atual e decisões pendentes.
2. Abra o [guia de início](docs/iniciar-projeto.md) e o [índice dos templates](templates/projeto/README.md). Selecione documentos por necessidade de comunicação, implementação, validação ou operação.
3. Consulte o [GitHub Project de referência](https://github.com/users/PHnsilva/projects/13) e seu [guia](docs/github-project.md). Use as views e issues que ensinem algo ao destino. Para aprender rastreabilidade, abra o [exemplo de reservas](exemplos/reservas-de-recursos/README.md).
4. Para comparar opções de frontend, backend e serviços, abra [arquitetura](arquitetura/README.md). Para comunicação visual, consulte [diagramas](diagramas/README.md). Para fundamentar uma decisão, busque a referência pelo tema no [catálogo](referencias/README.md), abra a fonte primária quando possível e registre edição ou versão. Para exportar ou validar documentação, identifique a ferramenta no [índice de tools](tools/README.md) e confirme dependências, entradas e efeitos antes de executar.
5. Use o vocabulário, dados, integrações, equipe e critérios do destino. Registre as referências relevantes e o que foi adaptado. Se uma fonte opcional estiver indisponível, declare o limite e use as fontes acessíveis. Confirme com o usuário quando a lacuna impedir uma decisão que mude o escopo.

## Limites para reaproveitamento

- Use o escopo aprovado como fonte de requisitos. Preserve os fatos verificados no destino e marque hipóteses, propostas e pendências com a evidência disponível.
- Reaproveite perguntas, estrutura e técnicas. Reescreva exemplos e aceite conforme o problema. Evite importar atores, regras, datas, estimativas, arquitetura, conteúdo corporativo ou backlog de outro projeto.
- Inclua um diagrama ou documento quando houver público e pergunta concretos. Um README pode cobrir um projeto pequeno. Amplie a documentação quando aumentarem as fronteiras, o risco, as responsabilidades ou as exigências de validação.
- Para cada issue que entrega comportamento, aponte requisito ou caso de uso e os critérios observáveis. Para trabalho transversal, aponte o artefato, o risco ou a decisão que dá origem à issue.
- Mantenha uma issue por entrega com aceite. Use links de dependência quando a ordem importar. Use sub-issues quando uma entrega tiver partes verificáveis coordenadas pelo mesmo objetivo.
- Sua sessão precisa ter permissão para ler fontes privadas. Mantenha credenciais, dados pessoais, conteúdo corporativo e material sem permissão de reutilização fora dos exemplos.
- Escrita, abertura de issues, execução com efeitos externos e publicação seguem o escopo autorizado no destino. Cite caminhos, requisitos e resultados que você conferiu.

Antes de entregar, verifique se os links funcionam, se o escopo e as regras do destino aparecem nos artefatos e se cada entrega tem uma forma de validação. Qualifique separadamente testes planejados e resultados observados.
